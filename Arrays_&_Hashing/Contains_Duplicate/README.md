# Contains Duplicate\n\n**Problem Statement**\nGiven an integer array `nums`, return `true` if any value appears at least twice in the array. If every element is distinct, return `false`.\n\n**Core Challenges**\n- Recognizing that a naive O(n²) solution is easy but not acceptable for large inputs.\n- Choosing a data‑structure that gives O(1) average‑time look‑ups.\n- Discussing trade‑offs between time, space, and mutating the input (sorting).\n\n**Approaches**\n\n### 1. Brute‑Force (O(n²) time, O(1) space)\nCompare every pair of elements with two nested loops.\n\n### 2. Sort & Scan (O(n log n) time, O(1) extra space)\nSort the array and then check adjacent elements for equality.\n\n### 3. Hash‑Set (O(n) time, O(n) space) – Optimal\nIterate once, inserting each element into a `HashSet` (or `unordered_set`). If insertion fails because the element already exists, a duplicate is found.\n\n**Complexity Summary**\n| Approach | Time | Space |\n|----------|------|-------|\n| Brute‑Force | O(n²) | O(1) |\n| Sort & Scan | O(n log n) | O(1) |\n| Hash‑Set | O(n) | O(n) |\n\n**How to Explain the Transition in an Interview**\n1. Start with the obvious double‑loop solution.\n2. Point out its quadratic runtime and ask the interviewer if we can do better.\n3. Propose sorting – it reduces the problem to a linear scan but still mutates the input and costs O(n log n).\n4. Finally suggest using a hash‑based set for constant‑time membership checks, achieving linear time at the cost of extra space.\n\n**Edge Cases Interviewers Love**\n- Empty array `[]` → `false`.\n- Single element `[1]` → `false`.\n- All elements identical `[2,2,2,2]` → `true`.\n- Large input size (10⁵‑10⁶) to test performance.\n- Negative numbers and zeros.\n\n**Mock Interview Follow‑up Q&As**\n1. **Q:** What if we are not allowed to use extra space?\n   **A:** We can fall back to the sort‑and‑scan method, which uses O(1) extra space (in‑place sort) and runs in O(n log n).\n2. **Q:** How would you handle a stream of numbers where you cannot store the whole array?\n   **A:** Use a Bloom filter or maintain a sliding window with a hash set, acknowledging possible false positives.\n3. **Q:** Can we achieve O(n) time without O(n) extra space?\n   **A:** Not in the general case for arbitrary integers; we would need constraints like a bounded range to use a bitmap.\n4. **Q:** How does the solution change if the array is read‑only?\n   **A:** Use the hash‑set approach because it does not modify the input.\n
